A LITTLE DEEPER

Capabilities & context

Read the results with confidence

Destination ≠ entry point

The destination is the n-tag key, or the key recovered from the signature. It may be private. With Spark, this is the Lightning service node—not the Spark wallet identity.

Alternatives ≠ payment volume

Each distinct real hint entry point gets one attribution per invoice. With no real hints, the destination is used. Multiple targets can receive the same amount attribution: don’t sum their amounts as volume.

Enrichment is opt-in

Only a manual lookup shares node public keys with mempool.space. Aliases and channel capacity describe today’s public network, not history or spendable liquidity. Unknown nodes aren’t necessarily private.

Query details, retry caveats & sources

The window uses payment creation time, not completion time. The charts still use the timestamp encoded in each invoice. Pending payments are excluded from both exports.

CLN stores individual payment parts. Success means at least one complete part; failure requires no complete or pending part in that group. Groups can be retried, so an invoice may appear in both exports. DISTINCT bolt11 deliberately deduplicates invoice strings rather than counting payment groups.

CLN’s status != 1 includes pending (0) as well as failed (2). Preimage checks are redundant for normal wallet data. With a unique id, completed_at adds nothing after id DESC.

LND uses payment-level status, not individual HTLC attempt status. The commands use its supported RPC via lncli instead of internal SQL schemas. The creation-date lower bound is inclusive. Missing invoices, keysend, and non-BOLT11 requests are skipped.

These are read-only snapshots, not a live monitor. Deleted payment history cannot be recovered. Read the commands before running them; keep exported invoice files private.
